# 07｜自动化与扩展

## 先判断是否值得自动化

适合自动化的流程通常具备：

- 高频重复；
- 输入结构相对稳定；
- 输出可以被明确验收；
- 异常能够被识别和交还给人；
- 错误影响可控且可恢复。

如果问题定义、口径和责任仍在频繁变化，先用人工 + AI 协作跑通，不急着定时。

## 自动化任务契约

```yaml
goal: 这次运行要改变什么状态
inputs: 权威输入与时间范围
dedup_key: 怎样识别重复事件
output: 唯一落点
acceptance: 什么证据算成功
exceptions: partial / blocked / no_new_items 怎样判断
wake_trigger: 等待事项何时重新出现
stop_condition: 什么情况下停止运行或升级给人
```

## 人机四条通道

| 通道 | 适用情况 |
|---|---|
| Human | 需要判断、沟通、批准或最终验收 |
| AI | AI 可以独立完成研究、起草、整理和检查 |
| Collaborator | 下一步由其他协作者推进，人只看异常和回执 |
| Waiting | 当前没有可执行动作，等日期或依赖变化 |

这能防止所有任务每天同时占用注意力。

## 自动化质量

至少记录：

- 成功、部分成功、阻塞和无新增的次数；
- 重复生成、错误关闭和漏项；
- 人工复核时间；
- 上游权限、认证和数据缺口；
- 自动产物是否真正进入后续工作。

## 规模化的危险

- 每个新问题都做一个自动化，维护成本会超过收益；
- 多个任务重复扫描同一来源，会放大噪声和资源消耗；
- 定时运行成功不代表上游信息完整；
- 生成了日报、周报或知识卡不代表有人使用；
- 自动化越多，越需要唯一状态源、断点和异常收口。

## 扩展顺序

1. 单次手动跑通；
2. 连续多次使用同一规则；
3. 固化输入、输出和验收；
4. 增加幂等与异常状态；
5. 安排定时或事件触发；
6. 观察两周真实错误；
7. 决定保留、合并或停止。
