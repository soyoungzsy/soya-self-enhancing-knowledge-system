# 01｜系统总览

## 目标

SOYA-个人自增强知识库系统的目标是让信息经过一条可追溯链路，最终改变判断、行动和人的能力。它不追求把所有内容都变成知识卡片。

## 六层系统

| 层 | 作用 | 典型内容 | 主要风险 |
|---|---|---|---|
| 输入层 | 接收真实世界信号 | 会议、消息、数据、阅读、人工修改 | 来源丢失、噪声过多 |
| 证据层 | 保存可回查事实 | 原文、数据口径、回执、截图说明 | 摘要冒充原文 |
| 项目层 | 维护当前状态与决定 | 项目厚文档、方案、风险、下一步 | 多版本和平行稿 |
| 判断层 | 沉淀跨项目机制 | 方法、反例、决策记录、适用边界 | 把假设升级成规律 |
| 执行层 | 将判断变成动作 | 工作台、Prompt、Skill、自动化 | 已执行冒充已完成 |
| 复用层 | 让下一次任务更好 | 规则、模板、修改记录、复盘 | 沉淀很多但从不调用 |

## 两种闭环

### 工作闭环

```text
目标 → 当前状态 → 下一步 → 下一棒 → 完成证据 → 关闭/继续
```

### 学习闭环

```text
来源 → 自己的初判 → AI扩展 → 反例与数据 → 修改理由 → 新情境迁移
```

只有工作闭环，系统会高效但人未必成长。只有学习闭环，系统会有想法但缺少结果。成熟的个人知识系统需要两者同时存在。

## 三个核心对象

### Canonical document

一个主题在当前阶段的唯一活跃正文。历史版本进入修改记录或 Git 历史，不在文件名中制造“最新版”。

### Evidence object

可以被重新打开、核对语境和时效的原始依据。它可以是会议标题、数据表、公开网页或明确的人工输入。

### Decision object

一条带适用范围的当前判断，至少包含：依据、反例、数据缺口、置信度和下一验证点。

## 成熟度不是文件数量

可以按四级评估：

1. **可找到**：资料有稳定位置和导航。
2. **可追溯**：来源、版本和修改原因可回查。
3. **可执行**：知识能转成下一步和完成标准。
4. **可学习**：真实结果会反向修正规则，且人能迁移判断。

## 最小成功标准

选择一个真实任务，验证：

- 第一次凭直觉能找到正确入口；
- Codex 能读取当前正文，不新建平行稿；
- 关键事实有来源，未知项没有被补造；
- 任务关闭时有真实证据；
- 复盘后至少一条规则被保留、修正或删除。
