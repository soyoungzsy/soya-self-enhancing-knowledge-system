# 04｜与 Codex 协作

## 两层指令

### 长期规则放进 `AGENTS.md`

适合保存：

- 文件与目录边界；
- 默认写作与沟通偏好；
- 权限、隐私和发布规则；
- 必须执行的验证命令；
- 团队共享的工程或知识治理约定。

### 本次任务写进用户请求

至少包含：

- 目标结果；
- 真实材料或目标文件；
- 范围与明确排除项；
- 不可改变的约束；
- 可以观察的完成证据。

官方文档说明，Codex 会读取全局与项目目录中的 `AGENTS.md`，并按从根目录到更深目录的顺序组合，离当前目录更近的规则拥有更高优先级：[OpenAI 官方文档](https://developers.openai.com/zh-Hans/docs/agent-configuration/agents-md)。

## 高质量任务契约

```text
目标：更新现有项目厚文档，形成当前可执行方案。
材料：会议记录、当前厚文档、最新数据口径。
范围：只修改项目正文和最近导航。
约束：不新建平行版本，不补造Owner、数据或完成状态。
完成证据：链接可用；关键数字有来源；下一步和停止条件明确；相关检查通过。
```

强模型需要清楚的目标和边界，不需要用僵化步骤替代判断。

## 日常协作顺序

1. 先让 Codex 定向读取当前项目、最近证据和相关规则。
2. 要求它指出事实、既有判断、推断和建议之间的差异。
3. 让它直接完成低风险、可逆的整理、起草和检查。
4. 涉及公开发布、真实发送、金额、关键账号或不可逆操作时，保留明确边界。
5. 修改后检查实际文件、差异和相关测试，再报告完成。

## 反方审查

重要判断进入执行前，至少检查：

- **失败路径**：什么触发条件会通过什么机制导致失败？
- **用户反例**：哪个具体人群或情境不符合当前假设？
- **数据缺口**：缺哪项数据会改变方向、边界或置信度？

输出只保留会改变决定的部分，并给下一验证点或停止条件。普通文案和低风险维护不需要独立反方报告。

## 并行与多任务

- 同一批重叠文件只允许一个写入者；
- 并行任务优先做只读研究或候选清单；
- 由主任务统一合并、写入和验收；
- 子任务“完成”不等于总任务完成；
- 批量修改先固定范围与排除项，再试修样本。

## 完成的定义

```text
产物真实存在
+ 目标状态确实改变
+ 与影响范围匹配的验证通过
+ 本次引入的问题已经解决
```

初稿、配置完成、安装成功、测试通过和端到端可用是不同状态，不能互相替代。

## 最值得长期积累的纠正

当人修改 AI 输出时，不只保存结果，还记录：

- 删除了什么；
- 改成了什么；
- 为什么改；
- 这是一次性偏好还是长期规则；
- 下一次什么任务应该调用这条规则。

稳定纠正进入 `AGENTS.md`、模板或 Skill；单次项目判断留在项目厚文档。
