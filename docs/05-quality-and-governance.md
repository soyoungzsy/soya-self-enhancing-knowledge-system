# 05｜质量与治理

## 知识笔记的最小属性

```yaml
---
author: Human + AI
created: YYYY-MM-DD
updated: YYYY-MM-DD
version: v1.0
change_summary:
  - 本次真正改变的内容
type: knowledge-note
status: draft
source_summary: 原始来源概述
source_assessment: B｜证据可回查；结论置信度中等
reading_status: unread
---
```

字段用于识别与筛选，不用于承载后台日志。模型、客户端、任务 ID 等技术信息进入运行回执或审计台账。

## 两个评级必须分开

### 来源可靠性

| 等级 | 定义 | 使用方式 |
|---|---|---|
| A | 原文、原始数据、官方机构或可回查一手证据 | 可作主证据，仍需确认是否支持具体结论 |
| B | 权威二手资料或能定位一手证据的复盘 | 可支撑工作判断，关键数字回查一手源 |
| C | 一般二手内容、模型总结、内部实践但证据链不完整 | 只作方向或待验证假设 |
| D | 来源缺失、不可访问或转述对象不明 | 不当作已核实事实 |

### 结论置信度

| 等级 | 定义 | 表达方式 |
|---|---|---|
| A | 直接证据支持，口径清晰，关键反例已处理 | 当前已确认，但保留边界 |
| B | 核心方向有支持，仍有外推或待验证环节 | 当前较支持，条件是…… |
| C | 合理解释或初步假设，证据不足 | 待验证假设 |
| D | 与证据冲突或关键前提缺失 | 当前不支持或需重做 |

一条 A 级来源不自动产生 A 级结论。

## 修改记录

属性只写本次摘要，正文保留逐次记录：

```markdown
## 修改记录

| 时间 | 修改者 | 修改内容概述 |
|---|---|---|
| YYYY-MM-DD | Human + AI | 建立初稿 |
```

缺失的历史不要补造，明确写“早期记录不完整”。

## 写入门禁

写前：

- 当前内容属于哪个知识域、项目和文档类型？
- 是否已有唯一活跃正文？
- 新建后从哪里进入？

写后：

- 没有新增根目录文件、临时目录或平行稿；
- 属性与链接有效；
- 创建日期没有被更新时间覆盖；
- 本次新增问题为零；
- 历史问题单独报告，不借机扩大清理范围。

## 移动与合并

移动、重命名或合并前：

1. 记录清单与哈希；
2. 建立可恢复备份；
3. 复制并校验目标；
4. 修复链接和自动化路径；
5. 确认目标可用；
6. 最后才退役空的错误入口。

备份中存在不等于活跃知识库完整。

## 状态真实性

| 状态 | 必要证据 |
|---|---|
| draft | 结构或关键事实仍可能改变 |
| in_progress | 当前有人或 AI 有可执行下一步 |
| waiting | 依赖未满足，唤醒条件清楚 |
| blocked | 权限、输入或能力缺失，有解除条件 |
| partial | 一部分完成，剩余项明确 |
| done | 验收标准满足，有结果证据 |

“已发送”“已配置”“已写文档”只证明动作发生，是否完成取决于目标。
