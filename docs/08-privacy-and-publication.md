# 08｜隐私与公开发布

## 三层内容边界

### 可以直接公开

- 通用方法、模板、目录设计；
- 官方公开资料和链接；
- 完全虚构的示例；
- 不依赖私有系统的检查脚本。

### 需要抽象后公开

- 从真实项目总结出的流程；
- 失败复盘和协作经验；
- 真实业务规则的结构；
- 内部工具的使用方法。

抽象时保留“问题—机制—边界—验证”，删除能够定位组织、人物、项目和时间的组合细节。

### 不公开

- 凭证、Cookie、Token、私钥、Webhook；
- 私有链接、内部仓库、系统 ID 和本机路径；
- 未授权的会议、消息、截图和数据；
- 客户、用户、同事及其可识别信息；
- 能被少量线索重新识别的精确日期、金额和罕见事件。

## 脱敏不等于替换人名

以下组合仍可能重新识别：

- 精确日期 + 罕见事故 + 团队规模；
- 精确金额 + 地点 + 项目阶段；
- 职级 + 独特措辞 + 会议上下文；
- 截图中的头像、群名、浏览器标签、二维码和文件路径。

公开案例优先彻底虚构；必须使用真实案例时，只保留方法成立所需的最少事实。

## 发布前检查

1. 确认目标账号、仓库名和公开可见性。
2. 检查 staged diff 与完整 Git 历史。
3. 运行密钥、本机路径、邮箱、电话和自定义敏感词扫描。
4. 人工检查语义重识别风险。
5. 验证相对链接、示例命令和许可证。
6. 使用公开 noreply 邮箱提交。
7. 推送后从未登录视角查看首页和文件列表。

## 如果秘密已经提交

1. 立即撤销或轮换凭证；
2. 不要只删除当前文件；Git 历史和缓存仍可能包含内容；
3. 按平台安全流程清理历史；
4. 记录事件和防复发规则；
5. 重新扫描后再恢复发布。

## 本仓库的扫描器

```bash
python3 scripts/privacy_scan.py .
python3 scripts/privacy_scan.py . --deny "InternalProject" --deny "RealCompany"
```

扫描器负责明显模式，人负责语义风险。两者缺一不可。
