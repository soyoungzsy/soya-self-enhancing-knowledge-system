# 02｜信息获取与证据处理

## 信息进入系统前先回答四个问题

1. 它来自谁、何时产生、在哪个渠道？
2. 它是原始事实、对事实的解释，还是行动建议？
3. 它影响哪个正在推进的项目或长期判断？
4. 缺失哪些信息会改变结论？

## 输入不是越多越好

常见输入分四类：

| 类型 | 处理方式 | 不要做什么 |
|---|---|---|
| 内部事实 | 保留原始入口、日期和口径 | 用摘要覆盖原始语境 |
| 外部资料 | 优先一手来源，记录访问日期 | 把搜索摘要当证据 |
| 人工反馈 | 保留原话与修改位置 | 把单个反馈外推成普遍规律 |
| AI 产物 | 标明它是推断或草稿 | 冒充原始来源 |

## 增量处理流程

```text
获取列表
→ 识别新增范围
→ 用稳定键去重
→ 读取完整内容
→ 区分事实/推断/建议/缺失
→ 更新唯一正文
→ 记录覆盖范围与异常
```

稳定去重键可以是公开 URL、事件 ID、文件哈希、会议 ID 或“日期 + 主题 + 参与对象”的组合。不要只按标题去重。

## 四种运行状态

| 状态 | 含义 | 正确表达 |
|---|---|---|
| complete | 目标范围已获取且已处理 | 已完成，覆盖范围为…… |
| partial | 取得部分内容，仍有明确缺口 | 已处理可见部分，缺少…… |
| blocked | 权限、认证或上游能力使任务无法继续 | 受阻原因、缺少项、解除条件 |
| no_new_items | 已成功检查目标范围，确实无新增 | 已完成检查，无新增 |

`blocked` 不能写成 `no_new_items`，旧累计快照不能写成今日新增。

## 外部研究原则

- 搜索引擎负责发现来源，一手页面负责支持结论。
- 价格、版本、政策、人物职位等易变化信息要记录核验日期。
- 多个转载不算多个独立来源。
- 找不到一手来源时，降低来源评级并写明边界。

## 降噪策略

完整读取与少量呈现可以同时成立：

- 后台保留完整覆盖与断点；
- 前台只展示会改变判断、行动或风险的变化；
- 相同告警合并计数，不重复制造任务；
- 无新判断时不新增知识卡片。

## 最小验收

- 能说清本次检查了什么，没有检查什么；
- 每条关键结论可以回到来源；
- 重复信息没有生成平行正文；
- 权限失败、数据缺失和真实无新增被正确区分。
